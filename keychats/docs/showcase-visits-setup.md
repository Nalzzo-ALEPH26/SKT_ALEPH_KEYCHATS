# 만들었어요 🔨 조회수 적용 안내

## 집계 기준

- 카드의 '방문하기' 또는 URL을 일반 클릭·키보드로 열면 **클릭 한 번마다 1회**를 집계합니다. 가운데 버튼 클릭도 집계합니다.
- 사이트 작성자 본인의 방문도 포함합니다.
- 같은 사람이 짧은 시간 내 다시 방문해도 별도로 1회를 집계합니다.
- 게시판 열기, 새로고침, 댓글 열기만으로는 집계하지 않습니다.
- 숫자는 다른 사람 수가 아니라 **KEYCHATS에서 외부 링크를 클릭한 횟수**입니다. 외부 사이트 로딩 성공 여부는 확인하지 않습니다.
- URL 복사 및 브라우저 메뉴를 통한 링크 열기는 집계되지 않을 수 있습니다.
- 정렬 옵션: 최신순 / 댓글많은순 / 조회수많은순 (동점이면 최신순).
- 자신의 클릭 결과는 서버 응답으로 표시되며, 다른 사용자의 클릭은 게시판 새로고침 시 반영됩니다.
- 기존 조회수는 유지되며, 과거에 누락된 방문 기록을 되살릴 수는 없습니다.

## Supabase SQL 적용 순서

1. **운영 KEYCHATS에서 사용하는 Supabase 프로젝트**의 SQL Editor를 엽니다.
2. `keychats/supabase/migrations/20261103010000_showcase_visit_counts.sql`이 **아직 적용되지 않았다면 먼저 1회 실행**합니다. 이미 적용했다면 반복 실행하지 않습니다.
3. `keychats/supabase/migrations/20261103113000_showcase_count_every_visit.sql`을 **1회 실행**합니다.
4. GitHub에 이 ZIP에 포함된 `keychats` 하위 파일을 원래 상대 경로 그대로 업로드하고, Vercel 배포가 Ready가 되면 게시판을 새로고침합니다.

주의: 새 SQL만으로는 처음부터 조회수 테이블이 없는 환경에서 정상 동작하지 않습니다. 처음 SQL과 새 SQL을 위 순서대로 적용하세요.
기존 게시글, 댓글, 누적 조회수, 테마 데이터는 삭제하거나 초기화하지 않습니다.
기존 방문 제한에 사용되던 `showcase_visit_checkpoints` 테이블은 호환성과 데이터 보존을 위해 남겨 두며, 새 집계에는 사용하지 않습니다.

## SQL 권한이 아직 없다면

코드부터 업로드해도 기존 게시글, 댓글, 외부 링크는 계속 사용할 수 있습니다.
그러나 **예전 SQL만 실행된 상태에서는 예전 방식(작성자 제외, 30분 재방문 제한)이 유지**됩니다.
최초 조회수 SQL 자체가 없으면 방문 수는 `—`로 표시됩니다.
나중에 SQL을 적용하면 코드 재배포 없이 새 집계 규칙이 동작합니다.

## 동작 검증

- A가 자신이 등록한 링크를 1회 클릭: +1
- A가 바로 다시 클릭: +1
- B가 클릭: +1
- 조회수많은순: 집계가 높은 사이트가 상단 표시
- 게시판 새로고침: 방문 수 변화 없음
- 동시에 여러 사용자가 클릭해도 PostgreSQL에서 원자적 증가

확인 명령: `npm test`, `npm run build`, `npm run test:e2e`, `supabase test db`.
브라우저·DB 통합 테스트에는 로컬 Supabase와 Chromium 실행 환경이 필요합니다.
