# 만들었어요 🔨 방문 수 적용 안내

## 집계 기준

- 카드의 '방문하기' 또는 URL을 일반 클릭·키보드로 실행하면 방문을 집계합니다. 가운데 버튼 클릭도 집계합니다.
- 게시판 표시, 새로고침, 댓글 열기만으로는 집계하지 않습니다.
- 본인 메모 방문은 제외합니다.
- 같은 계정의 같은 사이트 방문은 마지막으로 집계된 시각부터 30분 동안 한 번만 계산합니다. 여러 탭·기기에서도 같은 기준입니다.
- 숫자는 서로 다른 사람 수가 아닌 방문 횟수입니다. 외부 사이트의 로딩 성공·이용 완료를 확인하는 수치는 아닙니다.
- 주소를 복사하거나 브라우저 메뉴로 링크를 여는 동작은 집계되지 않을 수 있습니다.
- 카드는 '방문 12회'처럼 표시합니다. 클릭한 사용자는 서버에서 확인한 값으로 갱신되며 다른 사용자의 집계는 게시판 새로고침 시 확인할 수 있습니다.
- 적용 이전 방문 기록은 복원할 수 없으므로 0회부터 시작합니다.

## 적용 순서

1. 현재 채팅 서비스가 사용하는 Supabase 프로젝트에서 SQL Editor를 엽니다.
2. `keychats/supabase/migrations/20261103010000_showcase_visit_counts.sql` 전체를 실행합니다(최초 한 번).
3. ZIP을 압축 해제하고 저장소 최상위에서 `keychats` 폴더를 업로드하여 main에 커밋합니다.
4. Vercel 배포가 Ready가 되면 게시판을 새로고침합니다.

이번 SQL만 추가 적용하세요. 기존 메모보드·테마 SQL을 재실행할 필요는 없습니다.
GitHub에 ZIP 파일 자체를 올리지 말고 압축을 푼 폴더를 올립니다. 기존 파일/폴더를 삭제하지 마세요.

## SQL 권한이 아직 없다면

코드를 먼저 업로드해도 됩니다. SQL 적용 전에는 방문 수를 '—'로 표시합니다.
사이트 링크 열기, 메모 등록/수정/삭제, 댓글 등 기존 기능은 유지됩니다.
링크 열기는 집계 응답을 기다리지 않으므로 DB 오류가 사이트 이동을 막지 않습니다.
나중에 관리자가 새 SQL을 한 번 적용하고 게시판을 새로고침하면 됩니다. 코드 재배포는 필요 없습니다.
이 SQL은 기존 메모보드 기본 테이블이 이미 존재하는 환경에 적용하는 추가 마이그레이션입니다.

## 권한 및 보관

집계값은 편집 가능한 메모 테이블과 분리합니다. 일반 사용자는 집계값을 직접 쓰거나 초기화할 수 없습니다.
집계 RPC가 로그인 상태, 사용자 상태, 작성자 여부와 중복 방문을 DB에서 검사합니다.
같은 사용자 동시 클릭은 고유 키로 직렬화하고 다른 사용자 동시 방문은 원자적 증가로 처리합니다.
방문 기록은 사이트/사용자별 마지막 집계 시각만 유지하며 방문자 목록을 공개하지 않습니다.
메모 삭제 시 연결된 집계값과 마지막 방문 기록도 정리됩니다.

## 확인 방법

- A가 올린 사이트를 A가 클릭: 증가하지 않음.
- B가 클릭: 1회 증가. URL과 방문하기를 번갈아 눌러도 30분 내 추가 증가 없음.
- C가 클릭: 1회 추가 증가.
- 사이트 링크는 새 탭으로 열리고 새로고침 후 방문 수 유지.
- 30분 이후 B가 다시 클릭: 추가 증가.

검증 명령: `npm test`, `npm run build`, `npm run test:e2e`, `supabase test db`.
브라우저 및 DB 통합 테스트는 로컬 Supabase와 Chromium 실행 환경이 필요합니다.
